# 全量评分敏感性 v1：事后诊断协议

原始评分在逐题阅读中暴露提取问题。这个补充在不改生成、不选新配置的前提下，统一处理原 v2 `records.json` 的全部 2,336 条记录，包含所有原主确认条件及该 manifest 中的验证／消融／迁移条件。

**它是自动评分规则的事后敏感性分析，不是已经完成的全量语义裁决，也不替代原注册统计。** 规则设计使用了此前阅读中见到的错误类别；不是独立于结果的新主指标。全量运行前保存规则源码、输入 manifest、原 summary 与环境版本。原分数、选择、划分和报告均保留。

## 提取与匹配

提取函数只能读取回答全文、任务类型与原提取的后备值，不能读取参考答案、方法名称或正确标签。按以下优先级确定一个候选，不用“多个候选中有一个碰巧等于参考”来判对：

1. 最后一个完整、括号平衡的 boxed/fbox。
2. GSM8K 的最后一个 `####` 答案。
3. 最后一个明确 answer 标记，或最后一个 Therefore/Thus/Hence/So 结论。
4. 结尾的数学表达式；仍无结果时保留原 parser 的后备候选，并标记低可靠性。

结论中保留完整分数、根式、矩阵、进制下标。纯数字结论提取第一个答案数字，避免把后面的题目数量当答案；出现多个数字／数学表达式时显式标记。匹配前处理单变量赋值、空白及格式包装；数字沿用原 `rel_tol=0.001, abs_tol=1e-6`，符号等价使用已有 SymPy，递归转换分数和根式，限制语法和单次时间。不安装或升级 GPU 环境。

不支持的表达式、符号超时、长尾 boxed、后备提取、多个候选成分、生成截断均记入标记。**没有标记不代表已确认正确，有标记也不必然是评分错误。** 最终答案评分不验证完整证明。

## 统计与检查

- 全部记录均保存新旧标签、提取结果、规则、标记和原文件哈希。
- 所有改变标签的回答导出全文页面，供后续实际复核；页面生成不算语义核验。
- 原28项对照逐题重算，补充主确认 local8 / shared8、local8 / 三随机种子题内均值。
- 问题级2000次配对 bootstrap、seed9242026、逐项95%区间；区间仅反映抽题波动，未包含评分误差，不做新的候选选优。
- 独立审计脚本不导入提取器，核对覆盖范围、原始哈希、新旧标签对应、所有配对统计和报告文件。
- 解析 regression 是合成样例的实现检查，不是独立的评分准确度验证。符号用例必须在已具备 SymPy 的 Lambda 环境实际通过后再处理科学记录。

输出命名空间：`projection-first-v2-20260924/scoring_sensitivity_v1/`。如需更改规则使用新版本，不覆盖旧产物。GPU 不加载模型；无需新增生成。最终结论必须结合标记和实际复核，不能把自动统计的稳定性说成全量评分已经正确。
