结构细节在当前模型中有小幅贡献：Δh占比融合0.73410，加入同token跨层联合计数0.73912，再加入相邻token时间转移0.74215。后两步的增量区间分别为[0.00221,0.00787]、[0.00088,0.00512]。固定预测器下打乱前缀token次序，原始Δh轨迹AUROC从0.71575降到0.70722。这个乱序检查不等同于重训一个所有方面容量匹配的无序模型，也不能直接证明计算因果机制。

这些结果支持有限的额外风险信息，不能给某个token贴“错误步骤”标签，也未证明Δh是更通用的正确性表征。10%FAR在验证集选阈值，prefix64测试FAR实际为基线9.83%、Δh融合11.79%；不能把召回直接当成同一测试FAR的比较。各项区间是固定模型、逐项按题bootstrap，未做多重比较校正；标签仍是历史自动评分，数据已被多轮探索。

## 2. 更新重构能保留输出，但局部优势随位置变化

主功能设置：block14，已生成16个token，修改最后4个生成位置。保留完整本层输入，只重构并加回本层更新。对原模型下一token分布的平均KL：

| 条件 | KL |
|---|---:|
| 不改 | 0 |
| 删除更新、放回本层输入 | 0.02235 |
| 训练集全局平均更新 | 0.02106 |
| Δh簇中心 | 0.01902 |
| Δh中心 + 共享8维 | 0.01516 |
| Δh中心 + 对应局部8维 | 0.01341 |
| Δh中心 + 错配局部8维 | 0.01742 |
| 直接用h的局部8维重构整个状态 | 1.01471 |

Local8−Shared8 的KL差 **−0.001745，[−0.003745,−0.0000158]**，区间上界非常接近0；32个后续参考token平均NLL的差异区间跨0。Local8相对删除更新、错配局部基也有更低KL。仅簇中心相对全局平均更新的差异区间跨0，不能声称离散簇中心本身已获明确功能优势。

prefix64、修改最后4位置时，Local8 KL0.03467，Shared8 0.03110；差异+0.00357，区间[−0.00099,+0.01083]。该设置的参考NLL反而是Local8更高：+0.001361，[+0.000319,+0.002618]。因此不能把早期微弱局部优势描述为所有生成阶段都成立。

保留输入的Δh重构，和重构整个h的信息预算不同。即使完全删除这层更新，KL也只有0.02235；小KL部分来自原输入、其他位置和后续层仍保留大量信息。Local8在主设置仍有约80%的更新相对平方误差，不能把小输出KL称为更新向量几乎无损、整个状态8维压缩或准确率提升。zero_update也不是物理跳过block：原block计算的内部attention缓存仍存在。
