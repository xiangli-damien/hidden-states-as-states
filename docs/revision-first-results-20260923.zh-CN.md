# 首批结果：token mean 有用吗？

时间：2026-09-23。模型 Qwen2-7B-Instruct，MATH 5,000；训练/验证/历史测试 3,011/1,003/986。本页比较同一批 986 道测试题，原始 block 输出；第 28 层为 final RMSNorm **之前**。这些历史测试题已经被探索过，结论是探索性结果。

## 1. 生成过程中的窗口均值比单个当前位置更容易读出回答风险

相同 3,584 维表示、相同线性探针族；正则强度在验证集选择，训练集拟合读出标准化。聚类输入没有 normalization。生成时点指已经读入 16/64 个生成 token，均值仅使用该时点最近 16 个 token，没有使用完整回答。

| block / 时点 | last-token AUROC | mean16 AUROC | 配对差值及 95% 区间 |
|---|---:|---:|---|
| 14 / prompt | 0.803 | 0.808 | +0.005 [−0.006, +0.015] |
| 14 / 生成16 | 0.738 | 0.798 | +0.060 [+0.040, +0.082] |
| 14 / 生成64 | 0.742 | 0.765 | +0.023 [−0.001, +0.046] |
| 28 / prompt | 0.812 | 0.819 | +0.008 [−0.005, +0.020] |
| 28 / 生成16 | 0.710 | 0.798 | +0.088 [+0.063, +0.112] |
| 28 / 生成64 | 0.696 | 0.757 | +0.062 [+0.033, +0.090] |

区间为 2,000 次问题级配对 bootstrap，处理预测分数 ties；是 pointwise 区间，未作多重比较校正。

**当前支持的表述：生成阶段的局部均值保留了单个当前位置较难线性读出的、与最终回答成败相关的信息。** 生成前没有观察到稳定的 mean16 优势。它可以是跨 token 聚合降低位置特定噪声，也可以是多个位置携带互补信息；本实验还不能区分这两种解释。

prompt 的 mean16 是 chat 输入尾部，含指令/assistant 模板位置，不能等同题目正文均值。题目正文尾部另有独立 token 表示和干预对照。

## 2. 这不等于发现了独立的“计算 state”

离散 GMM state 加到 nuisance 基线后，增益明显小得多。基线含题型、难度、输入长度、当前表示范数、当前 next-token 熵和 margin；没有最终回答长度。

- block 28 / 生成16：0.7939 → 0.7981，增益 **+0.0043**，区间 **[−0.0046, +0.0138]**。
- block 14 / 生成16：0.7930 → 0.8018，增益 **+0.0088**，区间 **[+0.0018, +0.0160]**；这是未经多重比较校正的探索性小增益。
- 其余本页预定时点的 mean16 state 增量区间都跨零。

线性探针的 mean 优势和离散 state 的受控增益是两个不同问题。不能把第一项的 +0.088 写成 state 超出置信度的增益。GMM 拟合不使用标签，NB/LR 读出使用训练标签；这也不是完全无监督的正误检测。

## 3. 几何审计与必要修正

首批 64 个表示/层/时点组合共 768 个 GMM 候选，全部收敛，ICL 选择已逐项复核；16 个组合的最优 K 位于网格上界 64。不能把它们称作已证明的全局最优簇数。

首轮真实-token codebook 每题只取窗口中 4 个位置，测试却覆盖 16 个位置。固定 chat 模板会让未取样位置存在结构性的覆盖差异。因此，这批结果保留作抽样消融，**尚未用它们作因果结论**。正式干预改用独立命名空间中的全部 16 个训练位置，避免将位置覆盖不足误判为 state 无效。

新版本同时区分：GMM 中心附近的残差 SVD，与按每簇训练样本经验均值中心化的真正 local PCA。两者共享同一 GMM 分配，但不是同一种重构，也都不是 MFA。

## 4. 下一步的判别条件

1. 真实 1/4/16-token 重构是否保留同-prefix KL/NLL及自由生成行为；必须包含等总扰动能量对照。当前尚无这项结果。
2. MATH→GSM8K 冻结迁移。主比较提前固定为 block28 / 生成16 / mean16 对 last-token 的源域冻结 NB；两者使用相同 GSM8K 确认问题。所有其余视图完整报告，不在目标测试集挑最优设置。
3. 冻结 map 只校准读出、目标域重新拟合、训练样本量匹配，分别判断失败来自 label prior、读出还是几何域偏移。

GSM8K 全量 1,319 道正在采集。固定划分为 541 适配、242 验证、536 确认。采集过程会读取标签检查完整性（两道冒烟题也在确认划分内），但不以确认指标选择迁移方法；不宣称确认标签从未被任何运维工具查看。

## 5. 更强的对照：是否超过最初的 prompt 表示？（08:22 UTC 更新）

这一步直接对应“prompt-last 可能已经包含整道题的语义和难度”的疑问。使用同层、生成前的完整 3,584 维 prompt-last 作为基线，比较加入生成窗口后是否有增益。把两个连续向量直接拼接训练，不用训练集内监督预测作 stacking；标准化只在训练集拟合，C 只按验证 log loss 选择。聚类依旧使用原始数据。

已经完成并审计 **6 个设置、48 个读出、432 个 C 候选，全部收敛**；逐题预测、选择过程、文件 SHA 和配对区间均复核。所有下表比较使用相同的 986 道历史测试题。

| block / 时点 / 生成表示 | prompt + 当前控制 | 再加生成向量 | 配对 AUROC 增益及 95% 区间 |
|---|---:|---:|---|
| 14 / 16 / mean16 | 0.8041 | 0.8111 | +0.0069 [−0.0016, +0.0152] |
| 28 / 16 / mean16（本阶段主比较） | 0.8129 | 0.8148 | **+0.0019 [−0.0060, +0.0102]** |
| 14 / 64 / mean16 | 0.8047 | 0.8017 | −0.0029 [−0.0130, +0.0070] |
| 28 / 64 / mean16 | 0.8133 | 0.8015 | −0.0119 [−0.0210, −0.0025] |
| 14 / 64 / all_mean | 0.8046 | 0.8088 | +0.0043 [−0.0051, +0.0141] |
| 28 / 64 / all_mean | 0.8132 | 0.8099 | −0.0033 [−0.0118, +0.0052] |

这里的控制包括题型、难度、输入长度、prompt 与当前表示的 norm、当时 next-token 的 entropy/margin；`all_mean` 是已生成的前 64 token 均值，不是完整回答均值。仅 prompt 的末层 AUROC 为 0.8115；前 16 个生成 token 均值单独为 0.7979。

**目前更准确的结论：窗口均值胜过生成当前位置，但在这组线性读出中，没有检测到它超过初始 prompt 表示的稳定正增量。** 这兼容“重新汇集已有题目信息”，但没有证明它只包含题目语义，也没有证明生成过程没有新信息。加入更多特征后的负增益可能来自有限样本、噪声与正则化，不能解释成模型内部信息变少。

限制：这是已探索过的 MATH 测试集；区间为未校正的 pointwise 区间；48 个选择中 21 个位于 C 网格边界。新的有限 C 网格比第一批表示实验更宽，因此不能混用两个实验的单独分数作配对差值。离散 one-hot state 与数千个连续坐标共享正则强度，它的近零增量也不是 state 信息量的上界。输入文本基线是 TF-IDF 词/双词特征，不是语义编码器。

本地完整报告：`results/revision-conditional-information-20260923/report/index.html`。审计脚本：`scripts/audit_revision_conditional.py`。

## 6. 重构误差还需要排除模板效应

全部 16 个训练位置的新版 codebook 已完成 **6/6**，72/72 候选收敛；ICL、decoder SHA 和数组有效性审计通过。六个设置都选 K=64，上界问题仍在。

| block | chat prompt 尾部 token 的 GMM NMSE | 题目正文尾部 | 前 16 个生成 token |
|---|---:|---:|---:|
| 14 | 0.0562 | 0.7524 | 0.6680 |
| 28 | 0.0479 | 0.6629 | 0.5317 |

分母均为各自训练均值对应的中心化能量，因此跨列差异不是一个控制实验。

**08:26 UTC：位置／token 身份对照已经完成并审计。** 986 道测试题的 chat 尾部 16-token 序列完全相同。仅用每个窗口位置的训练均值（16 个中心），block14/28 的 NMSE 就达到 **0.0724 / 0.0643**，即解释 **92.8% / 93.6%** 的总体中心化能量；64 个 GMM 中心对应 **94.4% / 95.2%**。因此，固定位置基线解释了大部分总体能量。GMM 相比它仍减少约 22%–26% 的剩余误差，剩余部分不能直接视为不重要。

题目正文和生成 token 则不同：位置均值的 NMSE 为 0.91–0.97，GMM 为 0.53–0.75。按实际 token ID 的训练均值也能解释较多能量，但正文/生成需要 2,620/2,404 个 token 中心，远多于 GMM 的64；不能把这种比较称作同参数预算的胜负。正文测试有945道有效问题，chat/生成有986道；不同 view 的样本与分母边界均保留。

这些结果不证明 hidden state 只包含模板：同一 token 仍可根据前文问题具有不同的激活。它们说明**评估 token codebook 时，必须在固定位置／词身份基线之外检查几何和功能**。为此，在任何 GPU patch 结果产生之前，已把独立的 position-mean 干预加入重构和自由生成 pilot；窗口依然是实际1/4/16个位置。原始拟合与结果不覆盖。

本地完整表格及逐题误差：`results/revision-token-controls-20260923/report/index.html`；审计脚本：`scripts/audit_revision_token_controls.py`。
