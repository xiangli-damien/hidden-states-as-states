# 首批结果：token mean 有用吗？

时间：2026-09-23。模型 Qwen2-7B-Instruct，MATH 5,000；训练/验证/历史测试 3,011/1,003/986。本页比较同一批 986 道测试题，原始 block 输出；第 28 层为 final RMSNorm **之前**。这些历史测试题已经被探索过，结论是探索性结果。

## 1. 生成过程中的窗口均值比单个当前位置更容易读出回答风险

相同 3,584 维表示、相同线性探针族；正则强度在验证集选择，训练集拟合读出标准化。聚类输入没有 normalization。生成时点指已经读入 16/64 个生成 token，均值仅使用该时点最近 16 个 token，没有使用完整回答。

| block / 时点 | last-token AUROC | mean16 AUROC | 配对差值及 95% 区间 |
|---|---:|---:|---|
| 14 / prompt | 0.803 | 0.808 | +0.005 [−0.006, +0.015] |
| 14 / 生成16 | 0.738 | 0.798 | +0.060 [+0.040, +0.082] |
| 14 / 生成64 | 0.742 | 0.765 | +0.023 [−0.001, +0.046] |
| 28 / prompt | 0.812 | 0.819 | +0.008 [−0.005, +0.020] |
| 28 / 生成16 | 0.710 | 0.798 | +0.088 [+0.063, +0.112] |
| 28 / 生成64 | 0.696 | 0.757 | +0.062 [+0.033, +0.090] |

区间为 2,000 次问题级配对 bootstrap，处理预测分数 ties；是 pointwise 区间，未作多重比较校正。

**当前支持的表述：生成阶段的局部均值保留了单个当前位置较难线性读出的、与最终回答成败相关的信息。** 生成前没有观察到稳定的 mean16 优势。它可以是跨 token 聚合降低位置特定噪声，也可以是多个位置携带互补信息；本实验还不能区分这两种解释。

prompt 的 mean16 是 chat 输入尾部，含指令/assistant 模板位置，不能等同题目正文均值。题目正文尾部另有独立 token 表示和干预对照。

## 2. 这不等于发现了独立的“计算 state”

离散 GMM state 加到 nuisance 基线后，增益明显小得多。基线含题型、难度、输入长度、当前表示范数、当前 next-token 熵和 margin；没有最终回答长度。

- block 28 / 生成16：0.7939 → 0.7981，增益 **+0.0043**，区间 **[−0.0046, +0.0138]**。
- block 14 / 生成16：0.7930 → 0.8018，增益 **+0.0088**，区间 **[+0.0018, +0.0160]**；这是未经多重比较校正的探索性小增益。
- 其余本页预定时点的 mean16 state 增量区间都跨零。

线性探针的 mean 优势和离散 state 的受控增益是两个不同问题。不能把第一项的 +0.088 写成 state 超出置信度的增益。GMM 拟合不使用标签，NB/LR 读出使用训练标签；这也不是完全无监督的正误检测。

## 3. 几何审计与必要修正

首批 64 个表示/层/时点组合共 768 个 GMM 候选，全部收敛，ICL 选择已逐项复核；16 个组合的最优 K 位于网格上界 64。不能把它们称作已证明的全局最优簇数。

首轮真实-token codebook 每题只取窗口中 4 个位置，测试却覆盖 16 个位置。固定 chat 模板会让未取样位置存在结构性的覆盖差异。因此，这批结果保留作抽样消融，**尚未用它们作因果结论**。正式干预改用独立命名空间中的全部 16 个训练位置，避免将位置覆盖不足误判为 state 无效。

新版本同时区分：GMM 中心附近的残差 SVD，与按每簇训练样本经验均值中心化的真正 local PCA。两者共享同一 GMM 分配，但不是同一种重构，也都不是 MFA。

## 5. 更强的对照：是否超过最初的 prompt 表示？（08:22 UTC 更新）

这一步直接对应“prompt-last 可能已经包含整道题的语义和难度”的疑问。使用同层、生成前的完整 3,584 维 prompt-last 作为基线，比较加入生成窗口后是否有增益。把两个连续向量直接拼接训练，不用训练集内监督预测作 stacking；标准化只在训练集拟合，C 只按验证 log loss 选择。聚类依旧使用原始数据。

已经完成并审计 **6 个设置、48 个读出、432 个 C 候选，全部收敛**；逐题预测、选择过程、文件 SHA 和配对区间均复核。所有下表比较使用相同的 986 道历史测试题。

| block / 时点 / 生成表示 | prompt + 当前控制 | 再加生成向量 | 配对 AUROC 增益及 95% 区间 |
|---|---:|---:|---|
| 14 / 16 / mean16 | 0.8041 | 0.8111 | +0.0069 [−0.0016, +0.0152] |
| 28 / 16 / mean16（本阶段主比较） | 0.8129 | 0.8148 | **+0.0019 [−0.0060, +0.0102]** |
| 14 / 64 / mean16 | 0.8047 | 0.8017 | −0.0029 [−0.0130, +0.0070] |
| 28 / 64 / mean16 | 0.8133 | 0.8015 | −0.0119 [−0.0210, −0.0025] |
| 14 / 64 / all_mean | 0.8046 | 0.8088 | +0.0043 [−0.0051, +0.0141] |
| 28 / 64 / all_mean | 0.8132 | 0.8099 | −0.0033 [−0.0118, +0.0052] |

这里的控制包括题型、难度、输入长度、prompt 与当前表示的 norm、当时 next-token 的 entropy/margin；`all_mean` 是已生成的前 64 token 均值，不是完整回答均值。仅 prompt 的末层 AUROC 为 0.8115；前 16 个生成 token 均值单独为 0.7979。

**目前更准确的结论：窗口均值胜过生成当前位置，但在这组线性读出中，没有检测到它超过初始 prompt 表示的稳定正增量。** 这兼容“重新汇集已有题目信息”，但没有证明它只包含题目语义，也没有证明生成过程没有新信息。加入更多特征后的负增益可能来自有限样本、噪声与正则化，不能解释成模型内部信息变少。

限制：这是已探索过的 MATH 测试集；区间为未校正的 pointwise 区间；48 个选择中 21 个位于 C 网格边界。新的有限 C 网格比第一批表示实验更宽，因此不能混用两个实验的单独分数作配对差值。离散 one-hot state 与数千个连续坐标共享正则强度，它的近零增量也不是 state 信息量的上界。输入文本基线是 TF-IDF 词/双词特征，不是语义编码器。

本地完整报告：`results/revision-conditional-information-20260923/report/index.html`。审计脚本：`scripts/audit_revision_conditional.py`。

## 6. 重构误差还需要排除模板效应

全部 16 个训练位置的新版 codebook 已完成 **6/6**，72/72 候选收敛；ICL、decoder SHA 和数组有效性审计通过。六个设置都选 K=64，上界问题仍在。

| block | chat prompt 尾部 token 的 GMM NMSE | 题目正文尾部 | 前 16 个生成 token |
|---|---:|---:|---:|
| 14 | 0.0562 | 0.7524 | 0.6680 |
| 28 | 0.0479 | 0.6629 | 0.5317 |

分母均为各自训练均值对应的中心化能量，因此跨列差异不是一个控制实验。

**08:26 UTC：位置／token 身份对照已经完成并审计。** 986 道测试题的 chat 尾部 16-token 序列完全相同。仅用每个窗口位置的训练均值（16 个中心），block14/28 的 NMSE 就达到 **0.0724 / 0.0643**，即解释 **92.8% / 93.6%** 的总体中心化能量；64 个 GMM 中心对应 **94.4% / 95.2%**。因此，固定位置基线解释了大部分总体能量。GMM 相比它仍减少约 22%–26% 的剩余误差，剩余部分不能直接视为不重要。

题目正文和生成 token 则不同：位置均值的 NMSE 为 0.91–0.97，GMM 为 0.53–0.75。按实际 token ID 的训练均值也能解释较多能量，但正文/生成需要 2,620/2,404 个 token 中心，远多于 GMM 的64；不能把这种比较称作同参数预算的胜负。正文测试有945道有效问题，chat/生成有986道；不同 view 的样本与分母边界均保留。

这些结果不证明 hidden state 只包含模板：同一 token 仍可根据前文问题具有不同的激活。它们说明**评估 token codebook 时，必须在固定位置／词身份基线之外检查几何和功能**。为此，在任何 GPU patch 结果产生之前，已把独立的 position-mean 干预加入重构和自由生成 pilot；窗口依然是实际1/4/16个位置。原始拟合与结果不覆盖。

本地完整表格及逐题误差：`results/revision-token-controls-20260923/report/index.html`；审计脚本：`scripts/audit_revision_token_controls.py`。

## 7. 保留 token 簇的顺序，会比均值或频率更好吗？（09:25 UTC）

已经完成并审计 **6个设置、96个读出、864个正则候选，全部收敛**。固定同一16-token窗口，用全部训练位置拟合的原始 GMM（K=64）做最近中心分配。比较状态频率、有位置的状态 one-hot、相邻状态对频率，以及连续均值、当前位置、原始 token 身份等基线。C只按验证 log loss 选择；同题固定划分，逐题预测与每个候选都保存。

### 生成前16个 token：当前有序离散读出没有优势

| block | 连续均值 | 状态频率 | 有序状态 | 相邻状态对 | 原始 token 频率 |
|---|---:|---:|---:|---:|---:|
| 14 | **0.8028** | 0.6490 | 0.6438 | 0.6615 | 0.6820 |
| 28 | **0.7979** | 0.6675 | 0.6276 | 0.6534 | 0.6820 |

表内为相同986题的失败 AUROC。本阶段预定主比较是block28生成16的有序状态对状态频率，配对差值 **−0.0399 [−0.0671, −0.0114]**。有序状态加入初始prompt＋当前控制后，0.8161→0.8121，差值 **−0.0040 [−0.0109, +0.0029]**，也未检测到正增量。

这说明**当前K64离散压缩和这些线性读出没有充分保留连续均值里可读出的预测信息**。它不是“所有token轨迹都无用”的结论：只研究前16个生成token；有序LR是按位置相加的模型，状态对也是局部频率统计；连续均值与离散序列的信息／参数预算不同；未完成一般非线性序列模型或MFA局部连续坐标比较。96个C选择只有4个落在网格边界，但有限模型族的限制仍存在。历史测试集探索性、pointwise区间均保留。

### 为什么不能把“打乱后掉分”直接当作顺序证据？

这里出现了一个明确的反例。chat prompt尾部第28层：

- 状态频率 AUROC **0.75153**，有序状态 **0.75148**，几乎完全一样。
- 每题随机打乱状态，再分别重训／评估有序读出，seed42降到 **0.70861**。
- 但只根据簇ID，就能在独立测试题上以 **99.987%** 的准确率恢复它属于16个位置中的哪一个；第14层达到 **100%**。随机猜位置是6.25%。

因此，chat尾部的“无序频率”已经隐含了几乎完整的位置信息。打乱后的频率本身没有改变，仍保留原先的预测能力；有序读出掉分不能单独证明原模型依赖这条推理顺序。原序列里实际变化的“位置×簇”特征只有64/65列，打乱后成为1017/1024列，学习同一信息的统计难度也改变了。

生成窗口不像chat尾部那么极端，但簇ID仍能以 **32.6% / 30.2%** 的准确率恢复位置；正文窗口为20.6% / 24.0%。这个诊断仅表示相关和读出，不证明某个簇是推理步骤。生成窗口的簇ID还能识别约46.7% / 41.7%的当前token身份；簇的词汇成分也必须纳入解释。

**下一步的重点保持为功能重构：** 检查只保留中心，与保留局部连续坐标时，真实续写和正确率有什么差异。暂不扩大簇序列分类器网格。GPU重构仍在GSM8K采集之后排队，本节没有把预测结果写成因果结果。

完整结果与两张可导出的图：`results/revision-token-order-20260923/report/index.html`。逐题预测、代码序列、候选选择和审计文件均位于同一实验根目录。三种shuffle种子全部报告，没有挑测试表现最差的shuffle来夸大差异。

## 9. 真实多token重构已完成：簇中心之外的连续变化有功能价值（10:52–11:00 UTC）

完成 **64题、17,010个条件**，约51分钟。两个block（14/28）、prompt/已生成16token、1/4/16位置、15种方法；正文尾部与chat尾部分开。完整执行审计通过，所有方法和逐题原始结果保留。以下是历史测试集中的32题pilot（正文尾部30题）；另有32题验证结果单独报告。这仍是探索性功能实验，不是答案正确率或steering结论。

### 9.1 生成token不能只保留一个簇ID：局部连续坐标明显改善保真度

在第14个block，用重构替换前16个生成token，再继续计算：

| 方法 | 下一token分布 KL，越低越接近原模型 | 完整参考续写 ΔNLL，相对原始参考损失的变化 |
|---|---:|---:|
| 各位置训练均值 | 10.7263 | +0.07025 |
| 仅GMM簇中心 | 2.8985 | +0.03803 |
| 所属簇的局部PCA，保留8个连续坐标 | **0.6483** | **+0.02026** |
| 全局PCA，保留8个连续坐标 | 4.6101 | +0.04906 |
| 原激活加等范数随机扰动（对照，不是压缩） | 0.1028 | +0.00445 |

每题参考NLL先对该题的完整保存续写求token均值，再跨题等权。原始参考NLL为0.146827。局部PCA相对仅中心的**配对KL差值为−2.2502 [−3.1533,−1.3826]**；配对NLL差值为 **−0.01777 [−0.03020,−0.00974]**。验证集也出现同方向改善：KL差值−3.3003、NLL差值−0.01753，对应区间均不跨零。

这支持一个有限但有意义的结论：**在当前codebook和这些干预位置上，离散簇ID不能替代簇内连续变化；保留少量局部坐标，确实更能保留模型的原输出分布。** 这超出了“几何误差更低”的证据，但仍不能说明那些坐标对应某个推理变量，也不等于数学正确率更高。

容量限制必须保留：局部PCA使用64套局部基，参数量多于一套全局PCA；8个连续坐标也比一个离散ID携带更多信息。当前结果不是同总参数预算的最优性结论，且局部PCA不是MFA。固定GMM中心的残差SVD作为另一方法完整保存，趋势相近，没有冒充经验中心化PCA。

### 9.2 不能只归因于“改动范数太大”

对每个token匹配实际扰动能量，中心替换的KL为2.8985，随机扰动为0.1028；NLL的配对差为 **+0.03358 [0.02494,0.04489]**。因此，当前操作的破坏不能只用幅度解释，被移除的方向也有影响。

随机对照保留了原始激活，只在其上加噪声，所以**它不是更好的压缩器**。这个结果也没有单独识别“推理方向”。完整审计记录实际bf16能量偏差，最大约0.83%，没有假设浮点下严格相等。

### 9.3 “多改几个token”与“总共改得更多”必须区分

| 范围 | 完整替换成中心的 KL | 总能量固定为1-token预算、仅向中心移动的 KL |
|---|---:|---:|
| 1 token | 1.5112 | 1.5086 |
| 4 tokens | 2.5311 | 0.0687 |
| 16 tokens | 2.8985 | 0.0258 |

完整中心替换从1扩大到16个token，ΔNLL从+0.00664增加到+0.03803；同题差值+0.03139 [0.02228,0.04434]。但固定总预算时，较宽窗口在每个位置移动得更少，当前最后位置也受到更小扰动，效果方向相反。因此，不能把“扩窗后输出变化更大”直接叫作更强的机制证据；也不能把右列称作完整中心重构成功。

### 9.4 chat模板的高保真，不代表生成内容也能这样压缩

第14个block、16位置中心替换：chat尾部参考ΔNLL仅 **+0.00023 [−0.00029,+0.00080]**；生成窗口为 **+0.03803 [0.02841,0.05079]**；题目正文尾部为 **+0.05088 [0.03080,0.07715]**。各位置均值对chat也很接近原始参考损失。这与此前固定chat模板解释大量几何能量的诊断相容，但不同角色的信息时点/有效题目不同，不是纯粹语义效应的控制实验。

还有一个架构边界：在**最后block的output**替换过去位置，并不改变该block已经形成的KV；因此这些过去位置不能影响后续token。完整审计有2,745个此类null条件通过。chat/生成尾部的确定性替换从1扩到16，在最后block的NLL/argmax不变，KL最大数值差仅7.98e-9。这是实现应有行为，不是新发现。完整参考NLL还会稀释只影响下一token的变化，不能只挑高“loss recovered”来宣称保留了全部功能。

**下一步：** 独立自由生成正确率pilot已启动；随后完成GSM8K冻结迁移和受控donor反事实。当前结果让“簇ID＋局部连续坐标”成为值得继续检验的对象，但没有完成选择性数学纠错。

所有区间为2,000次问题级配对bootstrap的pointwise 95%区间，未校正多重比较；历史MATH测试已探索。完整540行方法表、864行配对方法表、288行宽度对照以及PNG/PDF图位于 `results/revision-foundations-20260923/functional/report/index.html`。

## 12. 受控因果任务：执行正对照修复，但任务能力前提没有通过（15:10 UTC）

先前counterfactual任务要求记住u，随后读入c和颜色，输出`(u+c) mod10 | color`。实际patch是后续输入之前的1/4/16个token，以及整个早期记忆区域；donor、同u对照、等能量随机、identity、末层架构null全部保存。不是只修改prompt-last。

第一版在input embedding反事实正对照失败时停止。诊断发现**原始下一token logits完全相同，但repetition penalty读取的token历史不同**：真实改写输入与只换embedding的input IDs不同，继承的1.05惩罚能导致不同输出。显式设1.0后，两者输出一致。旧29个case及日志完整保留；新`greedy-v2`目录重新运行，不覆盖不兼容结果，也没有放宽正对照。

新版80个配对case、每case16个patch条件全部完成并审计：token位置、真实改写正对照、identity、未来因果性、末层过去位置null、activation哈希与能量均通过。随机/真donor实际能量比最坏偏差约1.59%，保留bf16偏差而不声称严格相等。

但模型任务能力很低：显式记忆原任务仅 **5/19** 正确，隐式加法仅 **2/20**；两类改写输入也远低于预定90%门槛。80个case不是80个独立问题，正确率按唯一prompt去重。常见错误是输出u、忽略后续加c，另有格式错误。**这使该任务上的state-only因果解释失去必要前提，不能只挑少量原本正确的case作机制结论。** 这也不等于Qwen普遍不会算术。

进一步完成并审计了360次训练侧能力诊断：延迟抄回20题、一步取模100题、显式/隐式两种任务各用两种预定表述各60题；组合任务全部用train pairs，没有读取validation/test结果挑表述。第一次仅因Transformers5返回类型失败，尚无输出；修复后新v2目录通过360个真实tokenizer预检再运行。它用来区分记忆、单步计算和组合指令理解，不拟合state、不实施patch。
